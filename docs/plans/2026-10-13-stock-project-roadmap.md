# 台股追蹤與交易訊號研究：一個月專案計畫

狀態：供檢視的專案規格；尚未開始實作。
期間：2026-10-13 至 2026-11-12。

## 目標與成功條件

建立可在本機執行、可放到 GitHub、可讓其他人依 README 重現的台股研究工具：追蹤指定股票、保存歷史資料、產生可解釋的進出場訊號，並用回測與模擬交易評估。

- 市場：台股。資料介面區分上市與上櫃；先驗證少量上市股票，再擴充。
- 預算：免費優先。盤中每 60 秒查詢為目標；來源延遲與權限另行驗證，不宣稱免費即時資料已可用。
- 研究頻率：歷史日線；使用者已確認盤前規劃進場、持有數天至數週的波段交易。
- 產出：可安裝程式、追蹤介面、回測報告、測試、操作文件與 GitHub repository。
- 第一版不含實際下單、融資、放空、全市場高頻追蹤或獲利保證。

### 每日流程與交易計畫

1. 前一交易日收盤後：資料更新完成並通過品質檢查後，產生隔日候選名單與計畫草稿。
2. 開盤前 1–2 小時：人工複核重大公告、隔夜消息與來源狀態，確認、調整或取消計畫。第一版不自動對新聞評分。
3. 盤中：監控已確認計畫的進場條件、可接受價格區間及失效條件；資料延遲或過期時標示無法可靠判斷觸發，不將提示當作成交。
4. 持有期間：每日複核既有持倉、離場條件與剩餘持有期限，保留修改原因與版本。
5. 收盤後：保存未觸發、取消、模擬進出場與持倉紀錄，和原始計畫比較。

每筆計畫包含交易日期、股票代號、依據資料截止時間、訊號理由、進場觸發条件、可接受價格區間、初始停損、停利或移動停損規則、最長持有交易日數、資金與單筆風險設定、估算部位、取消條件及計畫狀態。

候選狀態為草稿、已確認、已取消、已到期；模擬交易另記錄待進場、持有與已離場。進場計畫當日未觸發即到期，持倉依離場規則延續。歷史版本不覆寫，部位計算依使用者設定或清楚標示的示範值，不自行假定實際資金。

歷史回測重現「當日收盤資料制定下一交易日計畫」；未保存當時可取得的盤前消息，不回填新聞判斷。只有日線時，無法精確重現盤中成交先後與成交量確認，因此先測試能以日線一致表達的規則並揭露成交假設。

建議 Python + SQLite + Streamlit。命令列負責資料下載、追蹤與回測，Streamlit 顯示最新行情、資料新鮮度、價格圖與訊號原因。擷取器與畫面分開，畫面重新整理不應額外造成大量 API 請求。

備選一：只做命令列與研究報告，交付較快但操作較不直觀。
備選二：主要用 TradingView/Pine Script，適合平台內研究，但不能直接替代本專案的外部自動資料管線。

## 第 3 週：進場、離場與回測（10/27–11/02）

- [ ] 搜尋離場方法，將來源、發布／查閱日期、規則、用途與限制寫入研究筆記；區分個人經驗與實證。
- [ ] 先比較兩個透明進場基線：均線趨勢與前期高點突破；參數在測試前登記。
- [ ] 比較固定停損／停利、移動或 ATR 停損、趨勢失效離場與持有天數上限。
- [ ] 固定停損、ATR 倍數與持有天數均是待驗證參數，並非直接投資建議。
- [ ] 建立事件順序：收盤形成訊號，最早下一交易日可成交價格進場。
- [ ] 模擬跳空、停牌、漲跌停無法成交、最小價格跳動、交易單位與現金限制。
- [ ] 日線同時觸及停損與停利時採保守順序並揭露，不能從日線猜測盤中先後。
- [ ] 依實作時的官方資料確認台股手續費、交易稅與適用標的差異；滑價可配置。
- [ ] 時間順序拆分研究期、驗證期與保留測試期；避免反覆調整最後測試期。
- [ ] 記錄倉位與單筆风险预算，產生每筆交易的進出場原因。
- [ ] 支援跨交易日持倉；交易計畫到期不可造成既有持倉自動消失。
- [ ] 報告含成本報酬、最大回撤、勝率、平均盈虧、交易數、資金曝險與買進持有基準。

驗收：用人工可算的小型合成資料測試交易引擎；排除未來資料；明確呈現不賺錢的結果；揭露固定觀察名單與存活者偏差。
